| **CR-15** ✅ | **Standards-anchored default RuleSets**: IEC TS 62446-3 (solar, measurement layer), ACI 117 + ASTM E1155 (civil, Phase 2); versioned templates, client-overridable. **Amended (DET-1c) — RuleSet role evolves from "classification-type spine (ΔT thresholds)" → "client-policy spine."** The learned model (CR-19) now OWNS the anomaly type: the classifier assigns the IEC TS 62446-3 category and it is persisted at the inference callback as the classification authority (`standardRef` + `classification`). The RuleSet no longer derives the type from a ΔT cutoff; it is the client's configurable POLICY that consumes the model classification + ΔT + confidence → `priority` (combine class + ΔT; a high ΔT escalates toward PROMPT, per the DET-1b posture), `routeTargets` (delivery routing), and an evidence-framed `recommendation`. Standards still anchor the measurement layer (`standardRef` on both model output and RuleSet); the client still adjudicates the consequence and the 100% human QA gate is unchanged (CR-12). | Ship defensible defaults without a co-developer; standards classify, client adjudicates (CR-12). The classification *science* belongs to the learned detector (CR-10/CR-19), not a hand-tuned ΔT cutoff; the RuleSet is where the *client's* routing/priority policy lives — the real product moat (adjudication + routing + registry), not the detection method. |
| **CR-16** ✅ | **Anomalies are created unbound.** `Anomaly.assetId` is **nullable** and a `spatialBindingStatus` enum `{ UNBOUND_REVIEW, BOUND }` defaults to `UNBOUND_REVIEW`. | **CR-20** ✅ | **Real auth via Auth.js v5** (M1-01) — email **magic-link** (no passwords), **database sessions** in Postgres; the session carries `{ userId, organizationId, role }`. Users are **concierge-provisioned** (seed) — **no self-serve signup** (CR-14): the adapter refuses to create users and sign-in is denied for un-seeded emails. Replaces the M0 stub reviewer; QA approvals stamp the real `reviewedById` and org scope derives from the session. **Enterprise SSO/SAML is a deferred provider decision.** RLS ships in **M1-02** as Postgres row-level security — defense-in-depth BEHIND the app-layer `organizationId` filters, never a replacement. Every Organization-scoped table (plus child tables via their parent, and the `Organization` root) ENABLEs + FORCEs RLS with `USING/WITH CHECK` policies keyed on the transaction-local GUC `app.current_org`. **Dual-role topology:** the runtime (app + worker) connects as a **least-privilege, non-superuser, non-BYPASSRLS role `datumzero_app`** that is SUBJECT to RLS, while migrations + seed run as the superuser via `directUrl` (bypass). A Prisma client extension binds the authenticated session's org through `AsyncLocalStorage`/`runWithOrg`, setting the GUC per tenant query. The **auth substrate** (`User`/`Account`/`Session`/`VerificationToken`) is RLS-EXEMPT — sign-in must resolve a user before any org context exists. | Automating legal/financial determinations demands a real, auditable actor behind every approval (CR-12). Magic-link keeps the surface small (no password store); concierge provisioning matches the M1 posture (CR-14); the thin session interface lets the provider swap later. |

| **CR-22** ✅ | **Manufacturer-agnostic radiometric decode behind a `RadiometricPort` registry** (M2-1). A radiometric capture decodes to a TRUE per-pixel temperature array (°C) via format-sniffing decoders — FLIR R-JPEG, radiometric TIFF, DJI R-JPEG — routed by detected format; **fails closed** on unknown format or colorized-only input (never guess a format, never fabricate temperature). **FLIR** extracts via `flyr` (EUPL-1.2, pure-Python) used UNMODIFIED — wrapped, never forked (SaaS-backend OK; revisit before on-prem/edge per `docs/LEGAL-REVIEW-BACKLOG.md`); the Planck conversion is exposed as a pure function. **DJI** uses the DJI Thermal SDK (DIRP; 0.1 °C ÷10 → °C) under **DJI EULA §14**: runs ONLY on DJI-captured imagery, called as-is (no modification/reverse-engineering); the SDK binary/source/headers AND the DJI wrapper module are Confidential — **never committed** (gitignored, loaded from an env-configured vendored path `DJI_THERMAL_SDK_PATH`, guardrail-enforced-absent); CI mocks the DIRP boundary. Delivered in ISOLATION (M2-1a) — NOT wired into the live pipeline; channel-preservation / real-ΔT / Validator tie-in / e2e / observability are M2-1b…f. | Colorized JPEG exports discard the radiometric channel, and treating 16-bit pixels as °C (the M0 placeholder in `_load_frame`) fabricates temperature — true manufacturer decode is required before any client-facing ΔT (CR-12/CR-19). Licensing mirrors the secrets posture: `flyr`'s light copyleft is fine wrapped for a SaaS backend; DJI's SDK is proprietary + confidential, so it is isolated behind an env-pathed, never-committed boundary like `secretVaultKey` (CR-05/CR-14 keep native adapters demand-driven). |
| **CR-23** ✅ | **Radiometric-only measurement; intensity-proxy provisional ΔT retired** (M2-1b). Supersedes the intensity-proxy portion of CR-19. `detect()` measurement is radiometric-only: ΔT is computed solely from true °C via `RadiometricPort`; the 8-bit `intensity_celsius_per_dn` fabricated-ΔT path is REMOVED (it contradicts CR-22's 'never fabricate temperature'). Classification and measurement are separated — the MobileNetV3 classifier runs on an 8-bit crop normalized FROM the radiometric frame (`_stretch_u8`) and is unit-tested directly on the 8-bit InfraredSolarModules crops (`test_classifier_iec_category.py`); `detect()` is tested on synthetic radiometric fixtures + 8-bit/unknown fail-closed. A capture with no usable radiometric channel FAILS CLOSED — a session data-quality failure (no crops, no POST, no anomaly), NOT a PENDING_QA anomaly (operator surfacing is M2-1d, the unknown-format QA event M2-1f). `delta_provisional` stays in the pinned callback schema for contract stability, always `False` on the OK path — a candidate for removal in a later contract revision. | Fabricating a ΔT from 8-bit intensity is exactly what CR-22 forbids, and a 'provisional' measurement in a work order undercuts the evidence-grade posture (CR-12/CR-19). Classification was never the problem — it belongs on 8-bit crops; only the *measurement* must be real. Channel preservation forced NO new storage decision: `store.get()` already returns the raw source of record byte-for-byte and the colorized `analytics_crop.png` is a separate written-back asset the detector never reads. |
